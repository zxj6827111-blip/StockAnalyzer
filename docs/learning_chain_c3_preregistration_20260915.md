> 目的：在**跑任何一次评估之前**把变体定义、评估口径、判据固定下来。
> 方案 `docs/learning_chain_remediation_plan_v2_20260913.md` 明确要求
> 「预先固定单因子/组合规则或折内选择」「块长不得看完显著性再挑」，
> 因此本文件是运行前的承诺，不是事后解释。

## 1. 变体定义（5 个，全部在同一窗口/资格集/脚本下）

| 变体 | 分数来源 | 关键约定 |
|---|---|---|
| `blend` | 修后现有模型 | `ModelTrainer`（LightGBM + XGBoost → isotonic 校准 → meta 权重混合），**取 `meta` 分数**，即当前生产口径 |
| `raw_blend` | raw/rank 路径 | 同一训练产物，取**校准前**的 raw blend。用于回答「校准是否伤害排序」 |
| `ridge` | ridge/线性 | 折内标准化（fit 只用折内训练段）+ `sklearn.linear_model.Ridge(alpha=1.0)`，**不接校准** |
| `stump` | 强正则单树 | 折内拟合 `DecisionTreeRegressor(max_depth=1, min_samples_leaf=max(20, ceil(0.01*n_train)))`，**不接校准** |
| `reversal` | 固定反转基线 | 分数 = `-ret_20d`（面板已含该 PIT 特征），**不训练**；按决策日做横截面排序 |

参数说明（为什么是这些值，避免事后调参）：

- `ridge alpha=1.0`：线性对照的目的是**证明非线性没有额外信息**，不是找线性最优；
  取默认量级并固定，不看结果再调。
- `stump depth=1`：方案原文是「强正则单树」，深度 1（树桩）是该族**最强正则端点**，
  也是唯一不需要再选第二超参的定义。
- `reversal` 用 `ret_20d`：反转基线的定义必须事先钉住一个回看窗口；选 20 日与面板既有
  特征一致（不引入新回看期），且 `ret_20d` 是 C1/Phase 2 口径下已确认的 PIT 特征。

**`raw_blend` 的实现约定**：`SignalPredictor.predict_rows` 现在只返回
`{"lgbm","xgb","meta"}`（均为校准后），且有 `test_predict_rows_empty_frame_returns_empty_lists`
按**精确字典**断言、`service.py` 亦在消费该返回。因此新增**独立方法**
（如 `predict_rows_with_raw()`）暴露 `raw_lgbm/raw_xgb/raw_blend`，
**不扩宽原返回契约**，避免动生产推理口。

## 2. 评估口径（三同：同窗口、同资格集、同脚本）

- 脚本：`backtest/walk_forward_xsec.py`（C1 修后的 verdict/覆盖门/移动块 CI 版本）。
- 折构造：`plan_folds` 按数据长度生成（C1 已去掉写死 18），`embargo_days = labels.horizon_days
  + execution_spec.settlement_lag`。
- 资格集（C4 第 1 项「先定未来实际推理的资格集」）：**先按当前生产口径**
  （`week5` 快照漏斗选出的候选池，即与 manifest 同源的那 335 只左右的横截面），
  再另跑一遍全市场口径作为**对照**；两者分开报告，不混合。
- 面板：复用已有两年 PIT 面板（2024-09-02 ~ 2026-08-28 / 2,405,272 行 / 5,191 只 /
  482 交易日），**不重建历史**。
- 每日分数先做横截面排序，再算指标；`reversal` 亦同（保证同口径）。

## 3. 每变体必报的量（C3 + C5 验收项）

1. **配对 OOS 增量**：与 `blend` 逐日配对差分（同一决策日、同一资格集），
   ΔIC 与 Δtop-bottom 各给**移动块 bootstrap CI**（块长 5 交易日，预设；
   同时附块长 1/10/20 作为稳健性，但不据其挑显著性）。
2. **错误相关性**：两变体的每日 IC 序列相关系数，以及 top 组命中集合的 Jaccard。
3. **分月/分板块稳定性**：按月给 ΔIC，列全部失效月（**不剔除**）。
4. **缺失与常数日覆盖**：无有效分数的决策日数、常数日数、每日有效截面中位数。
5. **成本与换手（C5 要求）**：`top_quantile_weights` 等权组合、单边成本 10 bps（预设）、
   日换手 `0.5·Σ|Δw|`、净收益序列；报成本前后对比。
6. **风险暴露**：组合相对全市场横截面的 beta、市值/板块分布偏离。

## 4. 判据（先定，后看结果）

- 变体相对 `blend` 的 ΔIC **只有在配对 CI 不跨 0 且方向为正**时才记「有增量」；
- 任何变体 **不得**仅凭全样本 IC 被认定有效；
- `reversal` 的作用是提供**成本后仍有超额**的对照下限；若某变体跑不赢成本后的反转基线，
  则该变体不具备可部署性（此条为硬判据）；
- 覆盖门沿用 C1：有效决策日数 / 常数日 / 前视违规=0 全部进 verdict 输入；
- 结果模板：每个变体一行，含 ΔIC[CI]、Δtop-bottom[CI]、换手、成本后净收益、失效月数。

## 5. 运行窗口与资源约束

- 评估属重活（Phase 2 记录过 5 类 OOM 根因），**必须在收盘后跑**，
  避免与 08:45 盘前 / 09:30 开盘 / 盘中 live_runtime 争 api 容器的 4 GiB cgroup；
- 每个变体单独一次运行（每 fold 新建 trainer，不跨 fold 复用实例——9/6 实测
  C 层分配器缓存累积约 1.6 GB），fold checkpoint 续跑；
- 与训练同源的 `learning_protocol.duckdb` 只读访问；不与写路径并发（9/14 实测过
  DuckDB 锁冲突会让整次训练 fail-closed）。

## 5.1 预检发现（2026-09-15 08:50，只读检查真实面板）

在跑之前核对真实面板 `artifacts/phase2_label_remediation/pit_dataset_rank/*.parquet`
（24 分片 / 214 列）后，发现两件必须在结论里讲清的事：

1. **面板是「214 特征世代」，与生产 222 维 schema 不同**：缺 `lp_m1_*`（7 列）与
   `__random_baseline__`，214 + 8 = 222 恰好对上。即本面板生成于那 8 个特征加入之前。
   → 因此本 harness 的 `blend` 变体**不等于**「部署中的修后现有模型」，而是
   「同一 trainer 在 214 特征面板上的结果」。**相对类结论**（raw vs calibrated、
   线性/单树 vs 混合、全体 vs 反转基线）仍然有效，**绝对 IC 不得与生产口径对比**。
   → 选这块面板的理由是它与 9/8 那次 IC +0.0658 的参考结果**同源可比**；
     要产出生产可信的绝对结论，需要按当前 schema 重新生成面板（列入批次 D）。
   → 凡引用本结果，必须写「214 特征世代」这个限定词。
2. **universe mask 只在生成端生效**：`_universe_mask`（非 ST/非退市/未停牌/有成交）
   仅由 `pit_dataset.py:386` 在生成时应用；`fetch_eval_rows` 不再过滤（面板也不含
   `is_st/suspended/volume` 列，故 harness 里重新套用会直接 KeyError）。
   → 即评估集已是被过滤后的集合，**不需要**在 harness 侧再过滤；但也意味着
     过滤所依据的是生成当时的数据，跨世代比较需注意。
3. 资格集口径（本文件 §2 第 3 条）在 214 列面板上**只能**做全市场口径：
   面板不含「策略候选池」标记，无法从面板复现生产漏斗的 335 只资格集。
   → 故本轮只报全市场口径，**并把「资格集口径对照」标为未完成**，
     不得用它的数字代表生产资格集上的表现。
