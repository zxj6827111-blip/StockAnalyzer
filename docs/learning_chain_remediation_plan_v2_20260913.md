## 1. v1 中被推翻或降级的结论（先读这一节）

### 1.1 「结构性 embargo 实际生效」是错的

v1 的 F7 断言：切分按成熟日分组、同一成熟日不跨段，故 embargo 生效。**该断言不成立**，理由：

- 成熟日分组只保证 `max(前段成熟日) < min(后段成熟日)`，**不能**保证**标签在预测时已经可知**。正确判据是 `max(前段标签可用时间) < min(后段决策时间)`。
- 对 return_rank，标签依赖**同日整个截面**的收益，所以"标签可用时间"不是单行的成熟时间，而是该决策日截面的最晚成熟时间。
- 实测（`dataset_manifest_v2_8b250aa25009`）：

| 边界 | 前段最晚截面可用时间 | 后段最早决策 | 判据成立？ |
|---|---|---|---|
| train → calibration | 2026-08-10 | 2026-07-28 | **False** |
| calibration → test | 2026-08-26 | 2026-08-06 | **False** |

- 泄漏规模：calibration 全部 **4,002 行**在 test 最早决策时标签尚未成熟；test 中 **3,329 / 3,990 行**（覆盖 **15 个决策日**，含每天 330+ 行的主力日）的决策时间不晚于 calibration 最晚成熟日。
- v1 说的"只有 6 行跨段"是**决策日劈裂**的计数，不是**标签可用性泄漏**的计数——两者差两个数量级，v1 把前者当成了后者的上界。
- **口径说明**：审核报告给 train→calibration 边界是 3,340 行，我实测 3,006 行。差异来自"calibration 开始时"的取点定义（行级成熟日 vs 截面可用时间）。结论不受影响，但**验收判据必须写成可复现的形式**（见 A1），否则又会出一次口径分歧。

### 1.2 「有效样本量约 200」是未经测量的假设，且实测值高一个数量级

v1 用"120 决策日 ÷ 10 天 horizon ≈ 12 个独立时间块"乘"每天 10~30 个独立观测"得到约 200，并把它当作"必须降复杂度、isotonic 必然不成立、特征只能留 10~30 个"的支点。**这个支点删除了**。

实测（267 只 × 150 交易日面板，证券间相关矩阵）：

| 口径 | 平均两两相关 ρ̄ | 有效独立观测 N/(1+(N−1)ρ̄) | 特征值参与率 PR |
|---|---:|---:|---:|
| 原始收益（含市场 beta） | 0.1816 | 5.4 | 10.4 |
| **逐日截面去均值（与 v3 标签同语义）** | **0.0039** | **127.2** | 14.0 |

- 单日截面名义约 267 只；按相对收益口径有效独立下注约 **127**（PR 14 给出因子维度的下界）。
- 12 个时间块 × 127 ≈ **1,500**。考虑 ρ̄ 的估计不确定性（单个相关系数 SE≈1/√150≈0.08，ρ̄ 的 SE 约 0.005），区间大致 **850 ~ 3,000**。
- 因此：**"横截面太窄所以只能线性"不成立**。仍然成立的是——**12 个独立时间块太少**，这才是真正约束，且约束的是"时序泛化/regime 稳健性"，不是截面宽度。
- 连带作废的推论：isotonic「必然不成立」（它的真问题是实现缺陷 + 校准窗上模型反向，见 A2）、特征「必须砍到 10~30」（应改为"fold 内筛选，数量由数据决定"）、"两个 Brier 相近所以融合无意义"（应做配对 OOS 增量检验）。

### 1.3 「没有任何门禁拦得住常数模型」不准确

实测：把新工件的落盘指标输入现有 `evaluate_promotion_validity`（`learning/slot_occupied_nav.py:358`）：

```
valid = False
blocking_reasons = ['insufficient_hard_class_samples',
                    'insufficient_test_trade_dates',
                    'insufficient_unique_logical_samples',
                    'nav_compounding_explosion']
```

前三条是我未传 `test_stats` 导致的（训练链会传），但 **`nav_compounding_explosion` 由落盘指标单独触发**——即工件确实已被既有门拦下。v1 把它说成"登记通过就会上线"是错的：**登记 ≠ 批准 ≠ 发布 ≠ 热载**。

**但我要补一条审核没有强调的风险**：这道门拦下本工件的理由是 `dataset_nav_compounding_explosion`，而这个指标本身是已知的口径产物（逐笔全仓复利的 e44 问题）。**一旦该指标被重新设计或豁免，这个退化工件就没有任何检查能拦住了。** 所以输出健康门（B2）仍然必要，只是定位从"补缺失的门"改为"补与现有门不重叠的输出语义检查"。

### 1.4 L4 的修法要改写

v1 说"统一到成熟日轴、把记账改成实际 embargo 天数"。这两条都**不是修复**：把 `embargo_days` 记成 11 只是让字段好看，轴统一也只是换了个量法。真正的修复是按日 purge 标签可用性（A1）。

### 1.5 L8 的改动面被低估

v1 说去校准"改动很小"。实际已确认的概率消费者：`models/predictor.py:56` 输出/截断契约、`pipeline.py:1526` ProbabilityHealthMonitor、`pipeline.py:1557` cross-review、`signal/cross_review.py` 多个概率门槛、`signal/scoring.py:15` 的 0~100 加权分数、shadow 对照的 Brier/logloss。另外：剔除中间 40% 之后，这个概率是"两端样本中的正类概率"，**不等于全市场上涨概率**——即使保留 sigmoid，也必须先把目标事件写清楚。

### 1.6 三个数值要加口径限制

- **F4/F5**：工件输入列 223 个 = 222 个生产特征 + `__random_baseline__`。v1 探针把该列填 0.0，而训练时是按 seed 生成的真实随机列 → v1 的 0.5321 / 0.0555 / 0.4435 / 0.9187 不可作为验收常数。审核按当前 seed 重建该列后得到 lgbm raw 逐日 AUC 0.53511、全截面逐日 IC 0.04711、blend raw 0.53173、blend cal 0.50210。**方向成立，数值以审核口径为准。**
- **F11**：在服模型 AUC 0.331355 是它**训练时在自己 test 段**、且是 soup 标签下的指标，**不是生产滚动 OOS 实测**。用它推断"生产一直反向"过强。
- **F14**：40,000 → 24,018（60%）是**本次默认标签参数**的结果，不是所有数据的恒等比例。

### 1.7 「树模型不能靠翻符号修」的理由要换

v1 那句混淆了两件事：对**输入特征**取反，树通常能学到对应切分；对**已固定的最终分数**取反，排序必然反转。决策（不给在服模型翻符号）保留，但正确理由是：**在服模型相对于新标签的符号关系没有被任何有效评估建立过**（它的指标是在旧标签下算的），且缺少前向验证；不是"翻不了"。

## 3. 整改项（四批）

### 批次 A — 正确性（阻塞一切；不合入这三项，后面所有数字都不可信）

#### A1 真实时间隔离（原 L4 重写；最高优先级）

- **问题**：见 §1.1。当前切分允许"用于拟合的标签在预测时尚未可知"。
- **改法**：
  1. 以**决策日**为单位做 purge：拟合段（train+calibration）的**标签可用时间**必须严格早于评估段的**最早决策时间**；不满足则整体剔除整日截面（截面的标签是同日全体收益的产物，不能只删单行）。
  2. 保留完整决策日截面（审核强调：不要按单行删除导致截面残缺）。
  3. 额外交易日间隔单独记录（它是 purge 的副产品，不要与 horizon 混为一谈）。
  4. 门禁同时报告：决策日自然日跨度、有效交易日数、成熟日范围、标签可用性边界——四项都报，不以其中任何单项单独定合格。
  5. **不改** `min_test_split_window_days=20` 的数值，先修隔离再用新数据重验（审核意见，同意）。
- **验收（必须写成可复现判据，避免 1.1 的口径分歧）**：
  - 逐边界断言 `max(前段截面标签可用时间) < min(后段决策时间)`，两侧均取**决策日**粒度；
  - 报告实际剔除行数、被整体剔除的决策日数、额外交易日间隔、异常延迟成熟的样本；
  - 用 `dataset_manifest_v2_8b250aa25009` 作回归用例：修复后必须显式报出被 purge 的 3,329 行 / 15 日（或等价统计），而不是静默通过。
- **成本/风险**：小到中。风险是 purge 会明显缩小可用样本（12 个时间块可能变 10 个），这正是"当前评估过于乐观"的代价，必须如实暴露。

#### A2 校准器实现与阶梯契约（新增，来自 R2）

- **问题**：`models/calibration.py:56` 用 `searchsorted(x_right, scores, side="right")` 查询以**右端点**保存的阶梯值，整体错位一个区间（F16）。这不是算法选择问题，是实现缺陷——它让**所有**含多个区间的校准输出都错位，与本节要做的算法比较无关。
- **改法**：明确阶梯区间契约（左闭右闭/左开右闭）后修正边界查找；同时补齐并测试：重复分数的聚合、相等边界、越界、`to_dict/from_dict` 往返一致。
- **验收**：F16 反例必须通过（`predict([0.1,0.5,0.9])` 至少保证 0.1 落在第一区间）；补单元测试覆盖上述四项；**并记录一个前提**——修此行**不能**挽救本次工件（xgb 拟合后只剩一个区间，塌缩另有原因）。
- **成本/风险**：小（一天内）。但必须单独成一个 PR，便于审计"实现修复"与"算法选择"两件事分开。

#### A3 v3 标签契约的可重放性（原 R5）

- **问题**（F17）：分位参数进了 hash，却没进 `LabelPolicyRecord` 与 NAS 表；派生函数读的是**当前配置**。因此未来改配置后重训旧 manifest，标签会变而 policy id/hash 不变。v1 曾声称"数据集口径由 manifest 锁定"，对分位参数不成立。
- **改法**：
  1. 把 top/bottom quantile、drop_middle、min_cross_section 持久化进 `LabelPolicyRecord` 与表（注意 `extra="forbid"`，需按兼容方式加列并保留旧字段过渡）；
  2. 派生函数改为按 **manifest 契约**取参数，而不是当前 `self._labels`；
  3. 缺历史参数时**显式拒绝或受控迁移**，不静默按当前配置派生。
- **验收**：同一 manifest + 改配置后重放，标签逐行一致；本地复现审核的对照实验（同 100 条收益，0.3/0.3 → 60 条标签，0.2/0.2 → 40 条）在新路径下应受契约约束而不再随配置漂移。
- **成本/风险**：中（schema 迁移 + 调用点改造）。这是"契约门全过"不等于"可重放"的关键补丁。

### 批次 B — 度量与门禁

#### B1 raw / calibrated 分离与逐阶段账本（原 L2 + L7 合并）

- **改法**：每个底模与 blend、pooled 与逐日、过滤前后、有效/无效日期分母**全部标明**；工件与 registry 同时记录 `auc_raw` / `auc_calibrated` / 各自 unique 取值数 / 并列占比；新增"可确定性复算"的数据+代码+配置身份。
- **账本口径**（采纳审核的修正）：`进入阶段数 = 输出数 + 各互斥原因剔除数`，原因分 middle-40%、thin-cross-section、missing/non-finite return 等；**不要**把 v1 那个 `included_snapshot_count − dataset_rows = label_filter_dropped_rows` 当作恒等式（存在 purge/缺失/其他过滤时不成立）。
- **L2 的复算要求**（采纳审核）：以**完整数据的确定性一致**为首选，不接受"抽样差异"作为默认解释。注意 F4 的教训——随机基线列必须按 seed 重建。
- **验收**：给定工件身份，独立复算脚本与 registry 记录逐项一致。

#### B2 输出健康门 + 批准/发布/热载统一（原 L1 重写）

- **定位修正**：不是"补一道不存在的门"，而是（i）补现有门**不覆盖的输出语义检查**，（ii）把批准→发布→热载统一。
- **判据设计原则**（采纳审核，v1 的阈值方案作废）：
  - 移除 `positive_rate ∈ [0.30,0.70]` 这条**通用**硬门——审核反例成立：全部分数在 0.51~0.59、预测正率 100% 的输出可能 AUC=1、Precision@K=1，该门会误杀排序完全正确的模型；
  - `mean_prob_spread` 是"正负真实标签组预测均值之差"，依赖分数尺度，**不能在 raw/rank/probability 间复用同一阈值**；
  - `unique < 20`、`AUC 落差 > 0.30` 只能作为**待验证规则**，须按输出语义、每日截面大小、并列占比、基准性能设计；
  - **确定性失败立即 hard-block**（非有限值、常数输出、契约不匹配、检查中已明确失败的条件），经验阈值先 advisory。
  - **保留现有阻断项**，不得因新增门而移除。
- **加载边界**（F23）：热载校验不得只要求"任意 role 的 hash 命中"，且无 champion 时的 bootstrap 例外应有明确范围与审计留痕；训练入口的 `load_predictor` 分支同样受门约束。
- **留痕**：失败的工件与诊断证据要**保存**，赋予 blocked / quality_failed 等可审计状态，而不是丢弃。
- **验收**：本工件在批准、发布、热载三条路径**都被拒**且理由可查；审核给的误杀反例不被新门拒绝。

#### B3 身份链与在服模型审计（原 L5）

- **改法**：先把在服 `model_v1.json` 的**真实身份**（hash、旧标签契约、质量状态）记录下来，再评它是否有资格成为 champion。**反向登记不等于授予质量合格**（采纳审核）。
- **验收**：`role='champion'` 可查，其 `artifact_uri`/hash 与实际 auto_load 的文件一致；查清 bootstrap/热载旁路。

#### B4 选样内存（原 L6，范围扩大）

- **改法**：覆盖 `service` 选样 → manifest 构建 → 训练前质量复算 → 最终训练装配**全链**，SQL 下推过滤、分批回取、释放中间副本；单改 `service.py:9265` 不足以证明可在 4 GiB 完成。
- **验收**：4 GiB API 容器内完成全池训练不 OOM，且计入常驻服务占用；同时评估"独立训练 worker"的长期资源方案（不把"所有全市场训练挤进 API"当唯一架构）。

### 批次 C — 模型与数据比较（**先复用已有资产，不先重建历史**）

#### C1 流程级验证 vs 工件级验证（原 L3 重写）

- **问题**（F21）：`walk_forward_xsec.py` 每折重新训练，评估的是**训练流程**，不是"拿 9/13 固定工件回打历史"；重复用同一历史窗口挑标签/特征/模型之后，该窗口已成为**开发验证资产**，不能再称最终测试集。
- **改法**：
  1. 流程有效性：每折独立训练、选特征、拟合校准与融合参数，绑定同一版本配置与数据契约；
  2. 工件有效性：冻结工件后在它未参与开发/训练/校准的**后续数据**上做 shadow 或真正前向验证；
  3. 统一 `hard_gate` / verdict / 前视违规 / 覆盖门（当前 `ci_supports` 未进 verdict，须修）；
  4. 修 `date_block_bootstrap_ci`：现为按天独立重采样，应按**连续时间块**或预先规定的 HAC 类方法，块长不得看完显著性再挑；
  5. fold 数不写死 18，按数据长度/训练窗/标签窗/步长生成。
- **保留结论**：审核用圆形连续块 bootstrap 复算原 18-fold 报告（342 个有效日，IC 均值 +0.065810）：块长 1/5/10/20 日的 95% CI 分别为 [+0.053,+0.079] / [+0.041,+0.091] / [+0.036,+0.096] / [+0.034,+0.097]，**全为正** → 支持继续研究 return_rank，但不构成 9/13 工件可晋升的证据。原报告总 verdict 仍是 `INCONCLUSIVE`。
- **验收**：新门必须能拒绝审核给的本地反例（IC 均值 +0.01、CI [-0.032,+0.052]、`lookahead_violations_total=1` 却返回 GO_CANDIDATE）。

#### C2 输出语义与下游契约（原 L8 重写）

- **改法**：先定义输出语义（ranking_score / rank_quantile / 事件概率），**不把 rank 写回原概率字段**；盘查并改造 §1.5 列出的全部消费方；明确"中间段剔除后概率针对的是两端样本中的正类"，不自动等于全市场上涨概率。
- **顺序**：**先修 A2 的实现缺陷**，再做 raw/rank 与低参数校准的对照，最后才决定去留（采纳审核：本次没有充分证据直接选"去校准"）。

#### C3 同口径配对比较（原 L9 + L10 合并重写）

- **改法**：在**同一窗口、同一资格集、同一评估脚本**下，配对比较：修后现有模型、raw/rank 路径、ridge/线性、强正则单树、固定反转基线。报告配对 OOS 增量（而非并列指标）、错误相关性、分月/分板块稳定性、缺失与常数日覆盖。
- **特征数**：fold 内筛选（筛选、标准化、超参都只用折内历史）；**不预设 10~30**——数量由数据决定（采纳审核；v1 的预设已被 F19 削弱）。
- **验收**：每项给出配对增量与 CI；不得用全样本选择后的 IC 作为独立证据。

#### C4 资格集与已有 PIT 面板复用（原 L11 + L13 合并重排）

- **改法**（采纳审核的排序）：
  1. 先定义**未来实际推理的资格集**（不是"策略候选池"顺手改全市场，而是先明确目标）；
  2. **复用已有两年面板**（F20：2024-09-02~2026-08-28 / 2,405,272 行 / 5,191 只 / 482 交易日 / 3.6 G）打通生产链与研究链的等价性对照，而不是等五年重建完成；
  3. 审计/修复缺失字段与保真分级；
  4. 再按数据可用性把历史缺口渐进扩展到更多年份（年度 ZIP 索引覆盖 2000–2026，文件在位，但**不等于**已形成特征齐全、无幸存偏差的 PIT 面板）；
  5. **扩 lookback 必须同时处理行数 cap**（F22），否则历史不会变长而只是窗口平移；注意全市场扩到约 5,000 只后，同样的 cap 只装得下约 8 个完整截面。
- **注**：v1 说 Phase1/Phase2 的 IC 差异"只能由池子组成解释"过强（两阶段同时改了评估流程），v2 撤回该表述，改为"池子组成是候选解释之一，需在同一流程下对照"。

#### C5 反转基线与成本门（原 L12）

- **改法**：作为**基线**纳入 C3 的配对比较；预先固定单因子/组合规则或折内选择；报告成本、换手、风险暴露与失效月份。当前全样本 t≈−4.5 是诊断证据，**不能直接当独立显著性证据**。

## 附录 B：三次自我纠正（累计）

1. **"sidecar 文件丢失"** → 错。路径拼接漏了 `model_sidecars/` 子目录；实际 sha256 齐全。
