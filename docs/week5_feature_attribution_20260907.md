# Week5 方案 A 特征归因报告（2026-09-07）

> 数据：Phase 2 同一 PIT 数据集 `pit_dataset_ext`（240 万行 / 5191 只 / 482 交易日 / 208 特征）。
> 评估日：18 fold eval_dates 并集 **352 日**（2025-03-21 ~ 2026-08-28），与 Phase 2 NO-GO 结论同口径，零新样本选择。
> 工具：`scripts/week5_feature_attribution.py`（commit 443c145），结果 `feature_attribution_20260907T170151.json`。
> 口径：每特征逐日横截面 Spearman rank IC → 全期均值 + date-block bootstrap 95% CI + 分月均值。

## 1. 核心结论

**模型分数 IC = -0.024 的归因定案：208 个特征里 98 个全 NaN（无数据），有效的 110 个中 64 个 CI 显著为负、仅 6 个显著为正。模型不是学坏了，是喂它的特征栈整体就是反着预测的。**

- **负向信号高度一致且贯穿全期**：top |IC| 全部为负——动量（ret_60d -0.069）、趋势（trend_slope_60 -0.069、rsi24 -0.064、ma_gap/macd 族 -0.04~-0.06）、波动率（volatility_5/8/10/13/20 全 -0.04~-0.05）、量能（volume_ratio_60 -0.047、price_volume_corr20 -0.056）。
- **动量族 9 个全部为负 IC**，且分月方向稳定（18 个月里 13-14 个月为负，仅 2025-05/2026-02 转折、2026-04~06 出现一段 3 个月的正 IC 窗口——regime 切换，随后 2026-07 回到 -0.37 级别的强反转）。
- **这与三个独立证据完全闭合**：8 月回测"动量选池与过热门死锁"、终门诊断"过热模型拒买"、Phase 2 全市场 IC 转负。**根因是特征语义问题（该市场该时段动量反转占优），不是模型结构或训练 bug。**

## 3. 分月稳定性（时间维度）

- 负向 IC 不是少数极端月主导：ret_60d 在 18 个月里 5 正 13 负，负值月份分布均匀（-0.03 ~ -0.14），仅 2026-07 一个月到 -0.37。
- 2026-04~06 出现连续 3 个月动量正 IC（+0.03/+0.05/-0.01）——这正是 8 月回测的训练窗尾部。**8 月回测的"动量选池死锁"本质是模型在学"追动量"，而该市场 2025-03 以来 80% 的时间动量是反转信号。**
- 结论：这不是可以"等 regime 回来"的问题——18 个月里 13 个月动量为负，横截面反转是这个市场该时段的主导结构。

## 4. 重训方向建议（按优先级）

**方向一（推荐）：负向特征语义反转 + 特征栈瘦身**
1. 64 个显著负特征不剔除而是**翻转符号**（动量/趋势/波动率族改用反转语义：如 `rev_ret_60d = -ret_60d`），保留模型可学习的稳定结构；
2. 剔除 98 个全 NaN 特征（训练时是噪声常量列）；
3. 保留 6 个显著正 + 不显著堆；
4. 用 Phase 2 harness 同口径跑 18 fold 验证——**预期模型分数 IC 从 -0.024 显著转正**（如果特征翻转后 IC 仍是负的，说明还有别的泄漏/标签问题，那是下一个要查的）。

**方向二（保守）：先只做"剔除负向 + NaN 清理"重训**
不动语义，只删 64+98 个特征，看剩余 ~40 特征能撑起多少 IC。风险：剩余特征信息量薄（最强正向 OBV 才 +0.02），很可能 IC 不显著。

**方向三（不推荐）：维持现状等 regime 切换**
2026-04~06 的正 IC 窗口说明动量时段存在，但 18 个月 13 负的占比下，任何追动量的模型在该时段都是长期逆势。且方向一实际上同时抓住了两头（反转主导时正 IC、动量 regime 时模型可从其他特征学习）。

> ⚠️ **本节方向一已被 §6 双口径诊断推翻**（翻转符号对树模型无效；真问题是 label 与评估口径错位）。以下原文保留作记录，拍板请看 §6.1。

## 6. 双口径诊断补充（2026-09-07 晚，推翻方向一前提）

> 触发：模型 AUC=0.586（预测 TP/SL 标签相当好）与分数 IC=-0.024（排序收益反向）同时成立——两者不可能都"只是特征反向"。
> 工具：`scripts/week5_dual_metric_diagnosis.py`（fbee4b1），每特征补测对 **label**（TP 8% 先于 SL 5% 的路径标签）的横截面秩 AUC。

**结果：63 个显著负 IC 特征里 62 个对 label 的 AUC 显著 >0.5（pile B）；IC 与 AUC 的相关系数 -0.518。**

| 例 | IC（对 fwd_return） | AUC（对 label） |
|---|---|---|
| atr_ratio | -0.039 | **0.619** |
| volatility_20 | -0.047 | **0.608** |
| rsi24 | -0.064 | 0.566 |
| ret_60d | -0.069 | 0.558 |
| turnover_rate | -0.045 | 0.591 |

**解读——这不是"特征反向"，是 label 与 fwd_return 在教两件不同的事：**

1. **label（TP/SL 路径标签）奖励"彩票性"**：高波动/高动量的票更容易在 10 日内**先摸到 +8%**（触发 TP → label=1），因为它们日内振幅大。所以波动率族 AUC 高达 0.62——模型预测 label 的 0.586 AUC 主要就是这些特征撑起来的。
2. **但 fwd_return（期末收益）惩罚同一批票**：同一批高波动票的 10 日**总收益**均值更低（IC 全负）——摸到 +8% 的路径和最终赚钱是两回事，先涨 8% 再跌回的票 label=1 但收益平平，而低波动票反而更可能稳步收正。
3. **结论：Phase 2 NO-GO 的直接根因是标签定义与评估口径错位**。模型忠实地学会了"找容易先摸 +8% 的彩票票"（AUC 0.586 证明它学得不错），但选股系统要的是"排序后买入组合收益最高"（IC），两者在南辕北辙。

**由此修正 §4 方向一：**
- ❌ 原表述"翻转特征符号"对 LightGBM/XGBoost **无效**——树模型对特征取反不敏感（分裂点自己找方向），翻转不改变任何学到的结构。此前的方向一作废。
- ✅ 真正的修法是**统一 label 与评估口径**，三个层次任选（见 §6.1）。

### 6.1 修正后的方向（待拍板）

**方向一'（推荐）：label 改为收益排序语义**
把训练标签从"TP/SL 路径标签"改为与 IC 评估一致的**收益类标签**（如 fwd_return 的横截面分位：top 30% 为 1、bottom 30% 为 0），或直接用 fwd_return 做回归/learning-to-rank 目标。模型从此直接优化"排序收益"。TP/SL 语义不丢——它对应的是执行层（slippage/止损纪律），不该在训练目标里。
预期：IC 转正的特征（OBV 族等）直接被放大，动量/波动率的"彩票溢价"被剥掉。
风险：需要重验标签时间语义（Phase 0 的 T+1 open 锚点不变，只换 label 公式）；AUC 口径要换评估基线（分位 label 的 AUC 与 IC 天然一致）。

**方向二'：保留 TP/SL label，但评估/选股改用 label 语义**
承认模型学的是"彩票票"，选股漏斗直接用 P(TP 先触发) 排序，评估也用 label 命中率（AUC 0.586 已可用）。**但这不解决 fwd_return 负 IC——买到的组合仍可能不赚钱**，只是自洽。8 月回测"99% 利润来自 3 只票"正是这种彩票结构的体现。不推荐作为主路线，可作为对照基线保留。

**方向三'：先修 98 个 NaN 特征再重训（与方向一'不冲突，建议合并做）**
NaN 根因（9/5 回填字段未进 PIT 快照链）与标签问题独立。先修 NaN + 换 label 语义一次重训到位，避免"改一次验一次"的两次全量验证。

### 6.2 回答"能否彻底解决所有问题"

不能一次解决全部，但能按因果链逐层闭环：
- **本次解决**：Phase 2 NO-GO 的直接根因（标签/评估口径错位）+ 98 个 NaN 特征（数据链路缺口）
- **重训验证后解决**：模型分数 IC 转正（这是硬指标，18 fold 同口径复验）
- **仍未解决、留待后续**：
  - 2026-04~06 动量正 IC 窗口的 regime 识别（若要同时抓动量时段和反转时段，需 regime 特征/多模型，属 Phase 3 范畴）
  - 终门阈值（score_floor 60-70 与分数分布脱节，Phase 1.5 已诊断，待新模型分数分布出来后重新校准）
  - 执行层（slippage/涨停不可成交）在回测中的建模——8 月回测 0 成交死锁的另一半原因
- 换句话说：**这次修复把"模型方向性错误"这个根层问题解决掉，剩下的都是它的下游症状（阈值、死锁、分布），会在新模型重训后逐个重新校准。**
