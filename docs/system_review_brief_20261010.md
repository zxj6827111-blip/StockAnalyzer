# StockAnalyzer 现状核实包（2026-10-10）

用途：交给外部模型核实结论、挑战推断、并据此出整改方案。
本文件**自洽**：不访问仓库也能读；要复查的话每条都给了仓库内出处。
所有数字都是实跑读数，不是估计；凡是我自己不确定或已改口过的地方，都单独标出来了。

---

## 0. 系统是什么

A股分析与选股系统，长期运行在飞牛 NAS 的 Docker 上（api + scheduler-heavy + scheduler-critical + redis，
生产镜像当前提交 `2b0ab09`）。选股链路是一条九层漏斗：

```text
全市场 → 硬性资格门 → Quality300 → Light100 → Deep50 → 夜间观察池
      → 次日 14:30–14:50 尾盘确认 → 最终推荐（0–3 只/日，可为空）→ 成交与退出
```

本轮改造的业务口径（写进单一契约，训练/标签/线上/历史验证共用）：
每只参考额 1 万元、止盈 +8% / 止损 −5%、持有 5 个交易日（入场日为第 1 日）、
T+1、费用与滑点按日期版本冻结。新模型要预测的概率定义为
**"按这套规则退出时净盈利的概率"**，命名 `p_net_profit_5d_tail`，
与线上原有的综合分 / `p_meta` **不是同一个东西**，不许互相冒充。

验收分两半：**工程验收**（时区/跨日/停牌/涨跌停/T+1/费用/身份异常等 19 个场景，已过，
60 个测试名钉住）与**选股质量验收**（滚动 train/calibrate/test ≥4 折、
六项指标、相对三个对照臂提升 ≥5pp 且交易日分块 bootstrap CI 下界 > 0，
之后再要未来影子验证 ≥60 个完整交易日且 ≥100 笔成熟模拟成交）。
**后者至今未通过。**

## 1. 核心业务问题：现在选出来的票，上涨概率不高，而且现行分数是反向的

### 1.1 直接回测"系统真实打分并推送过的票"（最可信的一段）

数据源：生产信号库 `signal_snapshots`（164,805 条快照 / 157,571 条已成熟结局）。
只取 `feature_capture_mode = observed_snapshot` 且 `strategy = trend`
（事后重算的 `replayed_recompute` 在同一批胜率统计里会把结果抬高一个量级，这是这库上记过的坑）。
按上面那套尾盘规则重算成熟标签：**42 个交易日、1,344 条标签、1,219 笔成交、成交率 0.907**。

| 指标 | 读数 | 交易日分块 bootstrap 95% CI（2,000 次，seed 20261010） |
| --- | --- | --- |
| 净盈利率 | **0.3651**（445/1,219） | [0.3053, 0.4193] |
| 平均每笔净收益 | **−1.113%** | **[−1.793%, −0.461%]** ← 不跨 0，显著为负 |

对照"同一个全市场合格池"在 2026 段（125 决策日）的净盈利率 **0.3971** ⇒ 差 −3.20pp，
且池基线落在上面的 CI 内。**结论：系统的选择相对"从合格池里随便拿"没有显著优势。**

### 1.2 现行 `p_meta` 分数与结果是反向的（本包最想被挑战的一条）

同一 1,219 笔按 `p_meta` 分五档：

| 分位 | 分数区间 | 笔数 | 净盈利率 | 平均净收益 |
| --- | --- | --- | --- | --- |
| Q1（最低） | 0.065–0.205 | 243 | **0.5761** | +1.33% |
| Q2 | 0.205–0.260 | 243 | 0.4156 | −0.71% |
| Q3 | 0.260–0.267 | 243 | 0.3004 | −1.77% |
| Q4 | 0.267–0.285 | 243 | **0.1852** | −3.25% |
| Q5（最高） | 0.285–0.581 | 247 | 0.3482 | −1.16% |

Q1 − Q4 = **+39.09pp**，交易日分块 CI **[+13.19, +54.27]**（18 个共同交易日）。
另有两条**独立**证据同向：现行 `p_meta` 在 2026-07..09 时间外截面 Spearman IC = **−0.0058**
（60 个交易日，IC>0 仅 53.3%）；gold 总体 walk-forward 里 `p_meta` Top5 的 5d 净盈利 **34.3%**
**低于候选池自身 48.8%**。

**注意措辞强度**：Q1→Q4 单调反向、但 Q5 回升 ⇒ 只能说"这一段的排序方向是反的"，
不能说"倒过来用就赚"——这条关系是在这 1,219 笔上发现的，用同一批数据证明它有效就是循环论证。
（同一教训已经发生过一次：容量排序曾在合并样本上显示 +11~14pp，做预登记与分块走查后
缩水到 +1.54pp 且 CI 跨 0。）

### 1.3 新概率模型自己也没赢

2025 全市场段（**从未参与本轮任何设计决策**的一段历史，242 决策日 / 72,600 重放请求 /
71,568 条成熟标签 / 成交率 0.8693 / 池内净盈利率 0.4376）第一次让滚动四折跑进测试段：

- 四折校准 raw AUC = 0.6299 / 0.5087 / 0.5441 / 0.6190（都过了方向门）；
- 判定**未通过**，三项失败门全是实测：净盈利率 处理臂 **0.4085**（284 笔）vs 同池容量基线
  **0.4629**（525 笔）⇒ **improvement −5.44pp**；分块 bootstrap CI **[−11.16, +5.22]** 跨 0；
  处理臂平均净收益 **−0.40%**（基线 +0.05%）；尾部 p05 −5.18% vs −5.33% ⇒ 尾部没恶化。
- 换 4 特征的臂仍卡在校准段（raw AUC 0.4718 < 0.5，训练器按契约停机，不产出概率）。

2026 段（125 决策日）里两种特征集的校准读数逐位相同（0.4696 / 0.4720），
原因是**滚动折永远从最早那段开始校准**，往尾部追加月份改不了第 1 折。

## 2. 为什么赢不了：信息层面的四个已证实事实

1. **四类信息的方向在两段独立历史都不稳**。特征分四组（market_relative / trend_position /
   volume_liquidity / volatility_overheat）。2025 段 39 个连续 12 交易日窗里，
   11 条特征只有两条正向窗过半：`gap_up_pct` 22/39（校准 0.5249）与
   `avg_turnover_20` 20/39（0.5224）——**而后者正是基线已经在用的东西**；
   `market_relative` / `trend_position` 两族在 2025 与 2026 两段都系统性 AUC < 0.5。
2. **信息被复用**：`relative_strength` 与 `rank_ret_20` 的截面 Spearman **ρ = 1.0**
   （跨声明分组），即两个"不同信息"其实是同一个秩。
3. **截断偏向已大涨与高波动**（成立），偏向难成交（**不成立，方向相反**）。
4. **容量截断的质量效应跨月翻符号**：同一口径把候选池从 300 放宽到 3,400，
   4 月保留组高 4.38pp、5 月高 6.32pp、**3 月反而低 4.65pp** ⇒
   不能主张"一律放宽候选面"，也不能主张"截断在伤害选股"。

## 3. 池子与口径问题（会让任何比较失真）

1. **线上与研究侧读的列不同**。生产 `hard_eligibility` 当天淘汰大头是
   `roe_below_min` **1,309** + `debt_ratio_above_max` **162**，
   外加 board 242 / financial_data_incomplete 40 / low_float_market_cap 16 / stale 12 /
   low_avg_turnover_20 10 / insufficient_history 11（5,478 考虑 → 3,676 晋级）；
   而历史重放只读 `close/volume_ratio_5/turnover/avg_turnover_20/float_market_cap/
   is_st/is_delisting_risk/suspended` **八列**，不含 roe/debt。
   ⇒ 两边算的"合格池"不是同一个池，"系统 vs 池"的差值因此带偏。
2. **基本面不是 PIT**。仓库日线表里 2025 年那些行上的 `financial_report_date`
   最大到 **2026-03-02**、每月只有 2–3 种取值 ⇒ `roe`/`debt_ratio` 是"当前快照贴到历史行"。
   把它当历史某日的资格判定输入就是前视。**线上今天用它没问题**（当天的快照对当天决策），
   但**任何历史回测用它都是错的**。
3. **候选面被一次未留档的前置筛选遮蔽**：全市场按同一套硬门重算后，
   **74.8% ~ 79.0%** 的合格 symbol-day 不在实际使用的那份 900 只清单里（三次独立复现）。
   这是覆盖面事实，**不是**质量损失证明——那些票当时一条尾盘成熟标签都没有。
4. 那份 900 只清单在仓库里**没有产生它的代码**（已补 provenance：文件、sha256、生产者标为
   `unknown_not_recorded_in_repo`）。

## 4. 数据正确性缺陷（都已定位到代码行，读侧已闭合，写侧未改）

| 缺陷 | 事实 | 状态 |
| --- | --- | --- |
| 流通市值被兜底常量填成常数 | 三个 provider 各自有 `_DEFAULT_FLOAT_MARKET_CAP = 12,000,000,000.0`；写库那条 `fillna` 依赖的 `daily_basic` 调用外面套着 `except Exception: basic = pd.DataFrame()` ⇒ **采集失败被换成一个看起来合理的值且毫无留痕**。占位占比按年：2024 = 0.03%、2025 = 1.4%、**2026 = 44.8%** | 读侧已按"带版本的解释规则"处理（占位行不参与市值比较、阈值只从测过的值推、整天没得判就不落档）；**写侧要另开 ADR**（改 NULL 会牵动 src 下 26 个出现该字段的文件） |
| 精确涨跌停采集面塌方 | 研究库 7 月只剩 209 只覆盖，根因是同步时传了**池内那份** CSV，而全市场那份（776,108 行 / 5,633 只）一直躺在本地；远端独立补采 201,893 行与本地差集 **0 对** | 已重刷（6 月 117,724 行 / 5,613 只、7 月 129,003 行 / 5,621 只）。修完重跑 2026 段：标签 31,599 → **37,046**（补回 5,447 条），但净盈利率从 0.4053 **降到 0.3971** ⇒ 被挡掉的那批样本**比原样本更难赚钱，先前那个数被缺失数据抬高过** |
| 证券状态史被接口上限截断 | `namechange` 响应正好 10,000 行 ⇒ 那一类逐行 `coverage_complete = False` | 退市覆盖算已证明；ST/改名覆盖不算（就绪审计里保留为缺口） |
| 分钟数据窗口断档 | vendor 分钟包止于 **2026-07-17** ⇒ 9/16–9/30 的真实推荐**没法**按尾盘规则回测；2024 分钟包有，但没有 2024 的日线 RAW 独立来源，口径证不了 | 明确不用日线或开盘价顶替（这是计划里的硬约束） |

## 6. 禁止的推断（请外部模型也遵守，别替我"补结论"）

1. 不许把阈值 **0.60** 说成已证明的命中率——它只是初始选股规则；项目自身锁定 OOS 的
   绝对命中率上限只有 **43.3–45.0%**，同一处还记着 TopK 绝对净收益为负。
2. 不许把 bronze 样本占比说成生产模型的根因。
3. 不许用"事后重算"的快照与"当时真实观察"的快照混算任何一个胜率。
4. 不许用历史分钟数据不足时**拿开盘回测顶替**尾盘验证。
5. 不许把 74.8–79.0% 那个数字说成"损失了多少净盈利机会"——它量的是覆盖面。
6. 不许拿"发现这条关系的同一批数据"当这条关系的证明。
